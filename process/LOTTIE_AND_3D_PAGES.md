# Interactive picture pages: Lottie and three.js — handoff

Books behaviour found here is collected in `process/APPLE_BOOKS_BEHAVIOUR.md`, the reference for reading-system findings.

An exploration started 2026-10-24: fixed-layout EPUB pages that behave like a digital pop-up book, where the reader drags a thumb along the bottom of the page and the picture moves. The user built this kind of content before (the iOS app Picklets, and browser tools for simple interactive pages). Current themes: LEGO building instructions, with IKEA manuals next. The user's standing direction: keep it exploratory, don't over-engineer, discuss open design questions one at a time.

## The book

SEED.html project "Lottie Interaction 7", open in the user's Firefox and reached over the seed-bridge. Fixed layout, 320×460 viewport (`seedhtml:viewport`), `rendition:spread none`. Spine: title, page02, page03, page04, and page05 to be added.

Each page's source is one line of markup that the text transform passes through: `<div id="touchpad" class="container" data-src="../pageNN.json"></div>`. In the SEED.html preview, `data-src` is rewritten to a blob URL for the manifest file, which is how page scripts find their data in both the preview and the packaged book.

`OEBPS/Scripts/animation.js` (the user's, unchanged) loads each `.container[data-src]` with lottie-web (`Scripts/lottie.min.js`, full build), autoplay off. A drag that starts in the bottom strip (pageY > 380) maps leftward travel over 210 px (320 − 110 thumb width) to frames 0 → end. On release it eases back to frame 0, a third of the way every 25 ms. It cancels `touchstart`/`touchmove`, which is what stops Apple Books' page swipe on iOS.

`OEBPS/Styles/stylesheet.css` holds the page rules, including the LEGO 3D page's rules (added 2026-10-24).

## Where the tools are

All under `~/Projects/webgl-book-build/` (not a git repository).

- `lottie/build_watch.py`, `lottie/lego_step.py`, `lottie/minify.py`: Python generators that write Lottie JSON. Run with `python3 -I`. `lego_step.py <thumb-source.json> <out.json>` takes the thumb layers (indices 1–6) from `lottie/built/page03.json`; `minify.py <in> <out>` drops default-valued keys.
- `lottie/built/`: the JSON as delivered to the book, plus `page01-copy.json` (the user's original page01, the source of the thumb slider layers).
- `lottie/render-lottie/make_preview.py <anim.json> <out.html> <frame,frame,…>`: a self-contained page showing chosen frames with the bundled lottie-web 5.12.2.
- `lottie/render-3d/shoot.sh <progress 0–1> <out.png>`: renders the 3D page in headless Chrome, driving the real drag code with synthetic pointer events and passing the model as a blob URL, as the preview does. `stitch.py out.png a.png b.png …` puts screenshots side by side.
- `entry-lego.js` builds `dist/lego/three-lego.js`, a three.js bundle with only what the LEGO page uses plus LDrawLoader (565 KB): `npx esbuild entry-lego.js --bundle --minify --format=iife --target=safari16 --legal-comments=eof --outfile=dist/lego/three-lego.js`. It is separate from `three-bundle.js`, which belongs to the WebGL test book (`process/THREEJS_EPUB_PROTOTYPE.md`).
- `book-lego/lego3d.js` and `book-lego/lego.css`: the 3D page's script and styles.
- `ldraw-src/ldraw/`: the full LDraw parts library (complete.zip). `models/page05.ldr` is the model; pack it with `cd ldraw-src/ldraw && node packLDrawModel.mjs models/page05.ldr`, which writes `models/page05.ldr_Packed.mpd`, copied to `dist/lego/page05.mpd`.

Rendering checks that work: headless Chrome with a throwaway profile and `--allow-file-access-from-files --virtual-time-budget=2000 --screenshot`, on a file:// page that carries its data inline or as a blob URL; for WebGL add `--use-angle=swiftshader --enable-unsafe-swiftshader`. The Playwright MCP refused file:// and failed on localhost.

## How files get into the book

- The bridge only overwrites existing files: it cannot create files, add manifest items or create chapters. The user creates the chapter and the manifest item (for example a copy of an existing .json), and the agent writes the content.
- For anything large (generated JSON, bundles, models), the user imports the file from disk. Retyping a large file into `seed_write_file` is how a typo got into page03 once; when a bridge write is unavoidable, compare the returned hash with the local file's sha256.
- Writes to any .js need the user's diff review each time.
- Rewriting a manifest JSON does not re-render the preview; the user re-selects the page.
- Only one Claude session can hold the bridge port (8747). Claude Code's pre-started spare sessions launch bridges too, so whichever session starts first gets it. Check with `lsof -nP -iTCP:8747 -sTCP:LISTEN`.

## Lottie notes

- The format: top level `v fr ip op w h layers assets markers`; layer `ty` 4 shape, 3 null; shapes `gr sh el rc fl st tr tm rp`; static values `{a:0,k:…}`, animated `{a:1,k:[{t,s,i,o}…]}`; earlier layers and earlier items in a group draw on top. Spec: lottie.github.io/lottie-spec/1.0.
- lottie-web quirks found: a repeater that repeats a group holding another repeater scatters stray copies (use one repeater per row); a group's `tr` needs all its fields (a bare `{"ty":"tr"}` renders nothing); colour channels need three decimals; a shape layer (`ty` 4) without `shapes` throws.
- The badge pill layer (index 12345679) in the user's early files is a Lottielab leftover; remove it.
- Drawing artwork as coordinates is the weak point; geometry that can be computed (watch faces, isometric boxes and studs) works well.

## three.js / LDraw notes

- LDraw: a plain-text format; parts from the official library (3001 brick 2×4, 3032 plate 4×6; colour 4 red, 2 green); 20 LDU per stud, 8 per plate height, 24 per brick; −Y up; a part's origin is the centre of its top face. `0 STEP` marks building steps, which LDrawLoader records as `userData.buildingStep`; `lego3d.js` animates the part from the last step.
- LDrawLoader draws edges and conditional lines, the instruction-drawing look. Edge weight is still to be decided.
- The camera is orthographic on the isometric diagonal, scaled to match page04 (25 px per stud), so the two pages can be compared.
- Licences for anything published: credit LDraw.org (parts, CC BY 4.0) and keep three.js's MIT notice (at the end of the bundle).
- Apple Books constraints from the earlier WebGL work still apply (memory `threejs-epub-prototype`, `process/THREEJS_EPUB_PROTOTYPE.md`): fetches return status 0 (three's FileLoader accepts it); size canvases from CSS and re-measure on pageshow; image files reach scripts as blank placeholders.
- **iOS page swipe:** in Books on iPhone, cancelling `pointerdown` does not stop the page swipe; cancelling `touchstart`/`touchmove` does. `lego3d.js` now cancels touches in the bottom strip and keeps pointer events for the movement.
