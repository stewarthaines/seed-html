# SEED.html - Simple EPUB EDitor

A modern browser-based EPUB editor that transforms plain text into beautifully formatted ebooks. Built with Svelte, TypeScript, and modern browser APIs.

## Overview

SEED.html is a sophisticated EPUB editing application that runs entirely in your web browser. It enables authors to create, edit, and publish EPUB files using a simple plain text workflow with powerful transformation capabilities.

### Key Features

- **Plain Text to XHTML Transformation** - Write in plain text, publish as valid, accessible EPUB 3
- **Browser-Based** - No installation required, works offline after first load, installable as a PWA
- **Multi-Device Preview** - See how your book looks on different devices, with different Reading System configurations
- **Extensible Transform System** - Customize text processing with JavaScript (for auto-generated glossary, index, list of figures)
- **Accessibility-First Design** - Full keyboard navigation and screen reader support
- **Internationalization** - Available in multiple languages with RTL support for writing
- **Browser-based File Storage** - Uses OPFS and IndexedDB for persistent local storage

## Distribution

SEED.html is distributed under the terms of the MIT license. It is free to use, modify and distribute. In addition to the source repository it may be available in these ways;

1. **Web Application** - Access at [readitinabook.com](https://readitinabook.com) for immediate use
2. **Downloadable HTML** - Save locally from the above site for offline authoring by opening the SEED.html file from your device
3. **Embedded in EPUBs** - The core SEED.html app can be added to an EPUB as a non-manifest item, so it travels with the book for the life of that artifact
4. **npm package** - `npx seed-html` serves the full app (including the extensions and plugins catalogs the single file can't carry) on your own machine — see [seed-html](https://www.npmjs.com/package/seed-html) on npm

See [USER_GUIDE.md](./docs/user/USER_GUIDE.md) for detailed usage instructions.

## Alternatives

Why another EPUB tool? SEED.html is built for one job — authoring accessible EPUB 3 books in the browser from plain-text sources — rather than converting between many formats or laying out for print. Here is a quick comparison with other tools you might reach for. A ✅ marks a first-class strength, ⚠️ a capability that comes with caveats (see the note under the table), ❌ something deliberately out of scope, and a blank means it is simply not a goal of that tool. > ⚠️ **PDF export.** SEED can generate a PDF straight from your plain-text source, but it renders through the browser's own print pipeline (a Paged.js polyfill) rather than a print-typesetting engine, so fine layout control is limited — treat it as a convenience output, not a rival to InDesign. On Chrome and Edge the result is a _tagged_ PDF, a solid starting point for downstream accessibility treatment.

## Extensions and plugins

Extensions give a book its source format, its richer content and its layout. Each book chooses its own, and an extension's scripts and styles are packaged into the EPUB, so the book does not depend on SEED.html to display them. Plugins add tools to the editor itself; they are not part of the book.

#### Source formats

- **[AsciiDoc](extensions/asciidoc/)**: Write chapters in AsciiDoc, the plain-text format for technical writing: documentation, articles and books. Rendered by Asciidoctor.js.
- **[Carve](extensions/carve/)**: Write chapters in Carve, a Markdown-like markup with a formatter, linter and migration tools, suited to books that live a long time. Rendered by carve-js.
- **[Djot](extensions/djot/)**: Write chapters in Djot, a clean Markdown-like markup with a consistent syntax, suited to most books. Rendered by djot.js.
- **[Fountain](extensions/fountain/)**: Write screenplays in Fountain, with scene headings, dialogue and transitions laid out as a script. Rendered by Fountain.js.
- **[LaTeX](extensions/latex/)**: Write chapters in LaTeX, the classic language for structured and mathematical writing. Rendered by LaTeX.js.
- **[Markdown](extensions/markdown-it/)**: Write chapters in Markdown, the widely used plain-text markup, with attributes for classes and ids. Rendered by markdown-it with markdown-it-attrs.
- **[Org](extensions/org/)**: Write chapters in Org, Emacs's plain-text format for notes, outlines and documents. Rendered by org-js.
- **[Textile](extensions/textile/)**: Write chapters in Textile, a concise wiki-style markup from the blogging and CMS world. Rendered by textile.js.

#### Code blocks

- **[ABC Music (abc2svg)](extensions/abc2svg+jsyaml/)**: Engraves ABC music notation as SVG scores in the Bravura font, sized to fit the reading column.
- **[ABC Music (abcjs)](extensions/abcjs+jsyaml/)**: Draws ABC music notation as SVG scores, with staff widths that fit the reading column.
- **[Bricks](extensions/bricks/)**: Building-instruction pages for fixed-layout books, where readers put each step together part by part or turn the finished model.
- **[Bricks - Minifigs](extensions/bricks-minifigs/)**: Adds minifigures to Bricks pages: a standing and a seated spaceman, with heads, helmets and air tanks.
- **[KaTeX](extensions/katex/)**: Typesets mathematics in code blocks as MathML, so formulas display without any script in the book.
- **[Mermaid](extensions/mermaid/)**: Turns Mermaid code blocks into self-contained SVG diagrams: flowcharts, sequence, class and state diagrams, pie charts and Gantt charts.
- **[Neumes](extensions/neumes/)**: Turns lines of direction marks and syllables in code blocks into manuscript-style singing notation.

#### Chapter content

- **[Audio Clips](extensions/audio-clips/)**: Tap-to-play audio clips in the book, with a choice of play and progress indicators for each clip.
- **[Family History](extensions/family-history/)**: Turns each chapter's record of a person into a kinship panel, family trees, lifelines, portrait strips and a surname index, and checks the facts as you write.
- **[Impressum](extensions/impressum/)**: Adds a colophon to the book listing its extensions and embedded fonts, kept up to date automatically.
- **[List of Figures](extensions/list-of-figures/)**: Adds a list of figures to the book, built from the images in each chapter.
- **[Photo Regions](extensions/photo-regions/)**: Names the faces in a photograph: exploring the caption lights up each face, named people link to their chapters, and a detail shows one region on its own, linked to the full image.

#### Typesetting and layout

- **[Fleuron](extensions/fleuron/)**: Shows thematic breaks as a centred fleuron ornament in the text colour.
- **[highlight.js](extensions/highlight/)**: Colours the syntax of code blocks, using highlight.js.
- **[Prettier](extensions/prettier/)**: Reformats JavaScript code blocks to fit narrow, wide and full-width reading columns, using Prettier.
- **[Print Index](extensions/print-index/)**: Page numbers for a PDF's contents or index, taken from the print preview and shown only in the PDF.
- **[Prism](extensions/prism/)**: Colours the syntax of code blocks, using Prism.
- **[Responsive layout](extensions/responsive/)**: Fits chapter layout to the reading column: a comfortable line length everywhere, and figure layouts that adapt where the reading system allows.

#### Accessibility

- **[Figures](extensions/figures/)**: Turns captioned images into figures, so screen readers announce each image with its caption.
- **[Language Switching](extensions/language-switching/)**: Marks passages in another language so reading systems and screen readers pronounce and render them correctly.
- **[Print Page Markers](extensions/print-page-markers/)**: Marks where each page of the print edition begins, so readers can follow along with the paperback.

#### Libraries for transform scripts

- **[js-yaml](extensions/js-yaml/)**: Lets your own transform scripts read YAML, such as frontmatter options.

### Plugins

- **[Accessible PDF](plugins/accessible-pdf/)**: Writes a tagged, accessible PDF of the book as the browser lays it out.
- **[Audio Clip Editor](plugins/audio-clip-editor/)**: Records or picks audio, marks clips on its waveform, and inserts them into the chapter being edited.
- **[Photo Regions](plugins/photo-regions/)**: Draws regions on a photograph and names who is pictured, for the Photo Regions extension.
- **[Place Maps](plugins/place-maps/)**: Finds the places a chapter names and adds a small locator map for each to the book.
- **[Publish to Remote](plugins/publish-to-remote/)**: Sends the book to S3-compatible storage, Google Drive, Dropbox, WebDAV or a USB e-reader, with an OPDS catalog for each destination.

## Technology Stack

- **Frontend Framework**: Svelte 5 with TypeScript
- **Build System**: Vite 6
- **Local Storage**: OPFS (Origin Private File System) with IndexedDB fallback
- **EPUB Processing**: Browser-native Compression Streams API
- **Testing**: Vitest with happy-dom
- **Documentation**: Storybook for component development

## Development

This section is for developers maintaining or extending SEED.html.

### Prerequisites

- Node.js 20+ (LTS recommended)
- npm 10+
- Modern browser (Chrome/Edge 119+, Firefox 119+, Safari 17+)

### Setup

```bash
# Clone the repository
git clone https://github.com/stewarthaines/seed-html.git
cd seed-html

# Install dependencies
npm install

# Start development server
npm run dev
```

### Agent assistance (dev server and npm installation only)

The repo includes an MCP bridge (`scripts/agent-bridge.mjs`) that connects a coding agent such as Claude Code to the running dev app, so the agent works against your live project: it can read source files and settings, follow the transform pipeline, inspect the rendered chapter as you see it, and — with your in-app approval, per write — edit chapter sources, stylesheets, and transform scripts. Useful when debugging CSS, transform output, or reading-system behavior. The bridge also serves an authoring guide (`docs/AGENT_AUTHORING.md`) that teaches the agent the project's EPUB and pipeline constraints before it may write.

```bash
# One-time: register the bridge with your agent CLI
claude mcp add seed-bridge -- node scripts/agent-bridge.mjs
```

Then: start `npm run dev` and open the app, start the agent session (the session spawns the bridge and keeps it alive), and click **Allow agent assistance** (robot icon, sidebar footer). The connection lasts for the session; every agent action appears in an in-app activity feed, and writes prompt for approval individually.

This is a local-workbench feature only: the button and module are absent from production builds. Design and security model: [process/AGENT_BRIDGE.md](./process/AGENT_BRIDGE.md).
